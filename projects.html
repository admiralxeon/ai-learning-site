Projects

This page has nine hands-on projects, from beginner to advanced. The last two are MLOps projects: they show how to keep a model good in production. Each project uses the ideas of the modules. Do a project when you finish the modules that it uses. Names with a dotted line are technical names. Put the pointer on a name to see its definition.

Reading teaches you the ideas. Projects teach you to use them. This page has nine projects. Each project uses the ideas of one or more modules.

Project 1: Teach a computer to see

  • Beginner
  • About 30 min
  • Teachable Machine, a webcam

Uses: Module 1, Section 4 Module 3, Section 4 Module 4, Section 9

What you make: an image classifier that tells the difference between two objects, for example a pen and a spoon. You train it with your webcam, in your browser.

Steps

  1. Open Teachable Machine. Select Get started, then Image project, then Standard image model.
  2. Change the names of the two classes, for example "Pen" and "Spoon". These are the labels.
  3. For each class, select Webcam. Hold the object in front of the camera and record approximately 100 images. Turn the object and move it, so that the images are different.
  4. Select Train model. The tool uses transfer learning: it starts from a network that is already trained on millions of photographs.
  5. In Preview, show each object to the camera. Look at the probabilities.
  6. Now test it with things that the model did not see: a different pen, your hand, an empty desk.

Check your work

  • The model gives more than 90% to the correct class when you show each object.
  • With an object that is in no class, the model still selects a class. It does not know “nothing”.
  • You can explain why: the model must put each image into one of the classes that you made.

Go further

  • Make a test for bias: train with images in bright light only. Then test in dim light. What occurs? Refer to Module 4, Section 9.
  • Add a third class “Nothing” with images of the empty desk. Does this solve the problem above?
  • Record only 10 images for each class. Is the model still good? This shows why the quantity of data is important.

Project 3: Build a spam filter

  • Intermediate
  • About 45 min
  • Python in Google Colab

Uses: Module 2, Section 7 Module 3, Section 10 Module 3, Section 4

What you make: a model that reads an SMS message and predicts "spam" or "ham" (not spam). It learns from 5,572 real messages. The model uses Bayes' rule for each word.

Python
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.feature_extraction.text import CountVectorizer
from sklearn.naive_bayes import MultinomialNB
from sklearn.metrics import accuracy_score, precision_score, recall_score, confusion_matrix

# 1. Load 5,572 SMS messages. Each message has the label "spam" or "ham" (not spam).
url = "https://raw.githubusercontent.com/justmarkham/pycon-2016-tutorial/master/data/sms.tsv"
data = pd.read_csv(url, sep="\t", header=None, names=["label", "text"])
print(data["label"].value_counts())

# 2. Divide the data: 80% for training, 20% for the test.
text_train, text_test, label_train, label_test = train_test_split(
    data["text"], data["label"], test_size=0.2, random_state=1, stratify=data["label"])

# 3. Change each message into word counts (the features).
vectorizer = CountVectorizer()
X_train_counts = vectorizer.fit_transform(text_train)
X_test_counts = vectorizer.transform(text_test)

# 4. Train a Naive Bayes model. It uses Bayes' rule for each word.
spam_model = MultinomialNB()
spam_model.fit(X_train_counts, label_train)

# 5. Measure the model on the test set.
spam_pred = spam_model.predict(X_test_counts)
print("Accuracy :", round(accuracy_score(label_test, spam_pred), 3))
print("Precision:", round(precision_score(label_test, spam_pred, pos_label="spam"), 3))
print("Recall   :", round(recall_score(label_test, spam_pred, pos_label="spam"), 3))
print(confusion_matrix(label_test, spam_pred, labels=["spam", "ham"]))

# 6. Try your own messages.
new = ["You won a free prize! Send your bank details now",
       "Are we still meeting for lunch today?"]
print(spam_model.predict(vectorizer.transform(new)))

Check your work

  • The data has 4,825 ham messages and 747 spam messages. The data is not balanced.
  • The accuracy is approximately 0.99, the precision approximately 0.99, and the recall approximately 0.94.
  • In the confusion matrix, approximately 9 spam messages are missed, and approximately 1 good message is marked as spam.
  • Your two messages are predicted as “spam” and “ham”.

Go further

  • Write a message that is spam but that the model does not find. Which words help you to trick it? This is how spam senders work.
  • Change CountVectorizer() to CountVectorizer(stop_words="english"). Do the results change?
  • Why is the recall lower than the precision? Which error is worse for a user: a missed spam, or a lost good message?

Project 4: Find groups of customers

  • Intermediate
  • About 40 min
  • Python in Google Colab

Uses: Module 3, Section 6 Module 2, Section 5

What you make: a k-means model that finds groups of customers in data that has no labels. Then you find the best number of groups.

Python
import numpy as np
import matplotlib.pyplot as plt
from sklearn.cluster import KMeans
from sklearn.preprocessing import StandardScaler

# 1. Make example data: 180 customers with two features each.
#    Feature 1: visits to the shop in a month. Feature 2: money spent in a month (rupees).
rng = np.random.default_rng(0)
students = np.column_stack([rng.normal(12, 2, 60), rng.normal(1500, 300, 60)])
families = np.column_stack([rng.normal(6, 1.5, 60), rng.normal(6000, 800, 60)])
workers  = np.column_stack([rng.normal(3, 1, 60), rng.normal(3000, 500, 60)])
X = np.vstack([students, families, workers])

# 2. Standardize the features (Module 2, Section 5), so that money does not hide the visits.
X_scaled = StandardScaler().fit_transform(X)

# 3. Try 1 to 6 groups. "Inertia" is the total distance from each point to its center.
for k in range(1, 7):
    km = KMeans(n_clusters=k, n_init=10, random_state=0).fit(X_scaled)
    print(k, "groups: inertia =", round(km.inertia_, 1))

# 4. Use 3 groups and show them on a chart.
km = KMeans(n_clusters=3, n_init=10, random_state=0).fit(X_scaled)
plt.scatter(X[:, 0], X[:, 1], c=km.labels_)
plt.xlabel("Visits in a month")
plt.ylabel("Money spent in a month (rupees)")
plt.show()

Check your work

  • The inertia decreases very much from 1 to 3 groups, and only a little after 3. This “elbow” shows that 3 groups is a good number.
  • The chart shows three clear groups: many visits with little money, few visits with much money, and few visits with medium money.
  • You can give each group a name, for example “students”, “families”, and “office workers”. The model does not know these names. A person gives them.

Go further

  • Remove the standardization (use X in place of X_scaled). Are the groups worse? Why? The money values are much larger than the visit values.
  • Change the number of customers in each group to 10. Is the elbow still clear?
  • Use your own data, for example the time and the cost of your trips. Do not use data about other persons without their permission.

Project 5: A neural network that reads digits

  • Advanced
  • About 45 min
  • Python in Google Colab

Uses: Module 4, Section 3 Module 4, Section 4 Module 3, Section 9

What you make: a neural network that reads handwritten digits from 0 to 9. The data is part of scikit-learn, so you do not need to download it.

Python
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split
from sklearn.neural_network import MLPClassifier
from sklearn.metrics import accuracy_score, confusion_matrix

# 1. Load 1,797 small images of handwritten digits. Each image has 8 x 8 = 64 pixels.
digits = load_digits()
X = digits.data / 16.0     # change the pixel values to numbers from 0 to 1
y = digits.target          # the label: the digit 0 to 9

# 2. Divide the data.
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.2, random_state=1, stratify=y)

# 3. Make a neural network: 64 inputs, two hidden layers (64 and 32 neurons), 10 outputs.
model = MLPClassifier(hidden_layer_sizes=(64, 32), max_iter=500, random_state=1)
model.fit(X_train, y_train)   # backpropagation and gradient descent happen here

# 4. Measure the model.
pred = model.predict(X_test)
print("Training accuracy:", round(model.score(X_train, y_train), 3))
print("Test accuracy    :", round(accuracy_score(y_test, pred), 3))
print(confusion_matrix(y_test, pred))

Check your work

  • The training accuracy is 1.0 and the test accuracy is approximately 0.98.
  • The difference between the two shows a small quantity of overfitting. Refer to Module 3, Section 9.
  • In the confusion matrix, most errors are between digits that look similar, for example 8 and 1.

Go further

  • Change hidden_layer_sizes to (8,): one small hidden layer. Is the model worse? Then try (256, 128).
  • Use only 10% of the data for training (test_size=0.9). How much does the test accuracy decrease?
  • Show the images that the model gets wrong. Would a person also make these errors?

Project 6: A prompt lab

  • Beginner
  • About 45 min
  • Any chat AI and a spreadsheet

Uses: Module 5, Section 7 Module 5, Section 5 Module 6, Section 6

What you make: a prompt for a real task, and a test that measures how good the prompt is. This is how professionals improve prompts: they measure, they do not guess.

Steps

  1. Select a task with a clear correct answer. Example: put customer messages into one of three categories: "Question", "Complaint", or "Order".
  2. In a spreadsheet, write 10 test messages. For each message, write the correct category. Include 3 difficult messages, for example a complaint that is also a question.
  3. Write prompt version 1: only the task.
  4. Use the prompt with each test message. Write the answer of the AI in the spreadsheet. Count the correct answers.
  5. Write prompt version 2: add the context, the format ("Answer with one word"), and two examples (few-shot prompting).
  6. Test version 2 with the same 10 messages. Compare the scores.
  7. Test version 2 again. Do you get the same answers? If not, use a lower temperature if the tool lets you.

Check your work

  • You have a table with 10 messages, the correct answers, and the answers from each version.
  • Version 2 has a higher score than version 1, especially on the difficult messages.
  • You can tell which part of version 2 helped the most.

Go further

  • Add a message that is in no category. Tell the model to answer “Other”. Does it obey?
  • Use the same test with a different chat AI. Which one is better for your task?
  • Make the test set larger: 30 messages. Is the difference between the versions still the same?

What you make: a test that finds if your spam filter from Project 3 works equally well for different groups of messages. Then you write a short model card: a description of the model for its users.

# Continue from Project 3 (the spam filter). Run this code after the code of Project 3.
from sklearn.metrics import recall_score, precision_score

test = pd.DataFrame({"text": text_test, "label": label_test, "pred": spam_pred})
test["group"] = test["text"].str.len().apply(lambda n: "short (< 60 characters)" if n < 60 else "long")

for group, part in test.groupby("group"):
    print(group, "| messages:", len(part), "| spam:", (part["label"] == "spam").sum(),

Project 8: Find drift and train again

  • Advanced
  • About 45 min
  • Python in Google Colab
  • MLOps

Uses: Module 7, Section 7 Module 8, Section 3 Module 8, Section 4

What you make: a monitoring loop for the mango checker. Each month, it compares the new data with the training data and measures the recall. When it finds a problem, it trains a new model (the challenger), compares it with the model in production (the champion), and updates a small model registry. In month 4, a new camera comes to the farm. It sees fewer spots on the mangoes.

Python
import numpy as np
from scipy.stats import ks_2samp
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import recall_score

rng = np.random.default_rng(7)


def make_month(n, new_camera=False):
    """Example data for the mangoes of one month: features X and labels y (1 = damaged)."""
    weight = rng.normal(250, 40, n)
    firmness = rng.normal(6, 1.5, n)
    spots = rng.poisson(1.5, n)
    y = ((spots >= 4) | (firmness < 3.5)).astype(int)
    if new_camera:
        spots = np.maximum(spots - 2, 0)    # the new camera sees fewer spots
    return np.column_stack([weight, firmness, spots]), y


# 1. Train the first model on 3,000 old mangoes. Put it in the registry.
X_train, y_train = make_month(3000)
model = RandomForestClassifier(n_estimators=100, random_state=1).fit(X_train, y_train)
registry = [{"version": 1, "month": 0, "status": "production"}]

# 2. Each month: compare the new data with the training data, and measure the recall.
for month in range(1, 7):
    X, y = make_month(1000, new_camera=(month >= 4))
    p = ks_2samp(X_train[:, 2], X[:, 2]).pvalue          # drift test for the "spots" feature
    recall = recall_score(y, model.predict(X))
    alert = p < 0.01 or recall < 0.90
    print(f"Month {month}: drift p-value = {p:.3f}, recall = {recall:.2f}", "<- ALERT" if alert else "")
    if not alert:
        continue

    # 3. Alert: train a challenger with half of the new data only. The old data comes
    #    from the old camera, so it does not agree with the new data any more.
    #    Compare the two models on the other half, which neither model saw.
    half = len(y) // 2
    X_new, y_new = X[:half], y[:half]
    challenger = RandomForestClassifier(n_estimators=100, random_state=1).fit(X_new, y_new)
    old_r = recall_score(y[half:], model.predict(X[half:]))
    new_r = recall_score(y[half:], challenger.predict(X[half:]))
    print(f"  Champion recall {old_r:.2f}, challenger recall {new_r:.2f}")

    # 4. Promote the challenger only if it is clearly better.
    if new_r >= old_r + 0.02:
        registry[-1]["status"] = "archived"
        registry.append({"version": len(registry) + 1, "month": month, "status": "production"})
        model, X_train, y_train = challenger, X_new, y_new
        print(f"  Version {len(registry)} is now in production.")

print(registry)

The drift test (the Kolmogorov-Smirnov test) compares two sets of values. A small p-value, for example less than 0.01, means that the two sets very probably do not come from the same distribution. Refer to Module 2, Section 5.

Check your work

  • Months 1 to 3 have a large p-value and a recall of approximately 1.00. There is no alert.
  • In month 4, the p-value is 0.000 and the recall decreases to approximately 0.47. The alert starts.
  • The champion has a recall of approximately 0.47 on the test half. The challenger has approximately 1.00. Version 2 goes into production, and version 1 is archived.
  • Months 5 and 6 have no alert, because the drift test now compares with the new training data.
  • You can explain why the challenger uses only the new data: the old data comes from a different camera.

Go further

  • Remove the drift test, and keep only the recall check. In real use, labels come late. Which check finds the problem first?
  • Change the camera effect from spots - 2 to spots - 1. Does the drift test still find it? Does the recall decrease as much?
  • Add the data version and the recall to each entry of the registry, and save the registry as a JSON file.
  • Try a professional tool for the same work, for example MLflow for experiments and a model registry.

Project 9: Ship a model with CI/CD

  • Advanced
  • About 90 min
  • A GitHub account, and Python on your computer or GitHub Codespaces
  • MLOps

Uses: Module 8, Section 5 Module 8, Section 6 Module 8, Section 7

What you make: a repository on GitHub with the mango checker service from Module 8. Each change goes through an automatic pipeline that trains the model, runs the tests, and builds the container image. Then you send a bad model, and you see the pipeline stop it. This project is a good first item for your portfolio. Refer to Careers, Section 5.

Steps

  1. On GitHub, make a new public repository with the name mango-checker. Select Add a README file.
  2. Open the repository in a codespace: select Code, then Codespaces, then Create codespace. A codespace is a computer in your browser with Python and Git. You can also copy the repository to your own computer with git clone.
  3. Make the six files of Module 8 in the repository: train.py and app.py (Section 5), requirements.txt and Dockerfile (Section 6), test_app.py and .github/workflows/ci.yml (Section 7). Use the Copy buttons.
  4. Make a file .gitignore with the two lines below. The pipeline makes the model again each time, so the model file does not go into Git.
    .gitignore
    model.joblib
model_info.json
  5. In the terminal, test everything on your computer first:
    Terminal
    pip install -r requirements.txt
python train.py
pytest
  6. Save the files in Git, and send them to GitHub:
    Terminal
    git add .
git commit -m "Add the mango checker service and its pipeline"
git push
  7. On GitHub, open the Actions tab. Look at the pipeline run. Select it to see each step: install, train, test, and build.
  8. Now send a bad model. Make a branch with git switch -c weak-model. In train.py, change RandomForestClassifier(n_estimators=100, random_state=1) to RandomForestClassifier(n_estimators=100, max_depth=1, random_state=1). Commit the change, push the branch, and open a pull request.
  9. Look at the pipeline of the pull request. Read the error of the failed test. Then close the pull request without merging it.

Check your work

  • On your computer, python train.py prints a recall of 0.98, and pytest shows 5 passed tests.
  • On GitHub, the pipeline of the main branch has a green check mark.
  • The pipeline of the pull request has a red mark. The weak model has a recall of 0.041, and the error is assert 0.041 >= 0.9.
  • You can explain an important point: the four API tests still passed with the weak model. Only the quality gate found the problem. Tests of the code alone are not sufficient for an AI service.

Go further

  • Add a load test: a test that sends 100 requests and fails if the slowest answer takes more than 100 ms. Refer to the story in Module 8, Part 8.
  • Make the pipeline send the container image to GitHub Container Registry, with the version as its tag.
  • Put the service on a cloud host that has a free plan, and add the address to your README.
  • Write the README with the template in Careers, Section 5.
