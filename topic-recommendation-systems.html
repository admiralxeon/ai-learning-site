Recommendation systems: how apps select what you see

This short topic is written in ASD-STE100 Simplified Technical English. Read Module 3, Machine learning and Module 2, Section 9 first. Shops, video apps, music apps, and news apps show each person a different list. This topic tells you how they select it, how teams measure it, and what risks it has.

1

Scope

A recommendation system predicts which items a person will probably like, and shows those items first. An item can be a product, a video, a song, a job, or a news article. This topic gives a description of the two main methods, the stages of a large system, how to measure it, and its risks.

2

Two main methods

MethodThe ideaIt needs
Content-based filtering"This is similar to what you liked."Information about the items, for example the type, the price, or the words in the description.
Collaborative filtering"People like you also liked this."The history of many users: what they bought, watched, or rated.

Collaborative filtering starts from a table of users and items. Most cells are empty, because each person used only a few items. The system must predict the empty cells. Refer to Figure 1.

3

How the prediction works

Modern systems learn an embedding for each user and for each item. Refer to Module 4, Section 7. The numbers are learned from the history. Often they agree with ideas that people can name, for example "sweet" and "sour".

The predicted score is the dot product of the user embedding and the item embedding. Refer to Module 2, Section 9. Example with two numbers (sweet, sour):

EmbeddingSweetSourScore for Sara (0.9, 0.1)
Alphonso0.80.20.9 × 0.8 + 0.1 × 0.2 = 0.74
Kesar0.70.30.9 × 0.7 + 0.1 × 0.3 = 0.66
Raw mango pickle0.10.90.9 × 0.1 + 0.1 × 0.9 = 0.18

The system shows the items with the highest scores first: Alphonso, then Kesar. Training changes the embeddings with gradient descent, so that the scores agree with the real history. Real systems use 32 to several hundred numbers for each embedding, not two.

The cold start problem

A new user or a new item has no history. We call this the cold start problem. Solutions:

  • Show popular items to a new user, or ask the user to select some interests.
  • Use content information for a new item, for example its type and price.
4

The stages of a large system

A video app can have millions of videos. It cannot calculate a full score for each video, for each user, each time. Thus a large system works in stages. Refer to Figure 2.

  1. Candidate generation. A fast method selects approximately 1,000 possible items, for example with a search for the nearest embeddings.
  2. Ranking. A more detailed model predicts the probability that the user will click, buy, or watch to the end. It uses many features, for example the time of day and the device.
  3. Rules. The system removes items that are not suitable and adds variety.

Each action of the user goes back into the data. Thus the system learns all the time.

5

How to measure recommendations

  • Before release: hide the last purchases of each user. Then check if the system recommends them. Precision at k gives the part of the first k items that the user really used. Example: 3 of the first 10 items were bought, so precision at 10 = 0.3.
  • After release: use an A/B test. Refer to Module 7, Section 6. Compare clicks, purchases, and returns.
  • Long term: do users stay satisfied after months? A system that gets many clicks today can make users leave later.
Caution

Divide the history by date, not at random. Train with the older history, and test with the newer history. Otherwise the model sees the future during training. This is data leakage. Refer to Module 7, Section 3.

7

Risks of recommendation systems

  • Feedback loops. The system shows popular items, so they get more clicks, so the system shows them more. New items and small sellers get few chances.
  • Filter bubbles. A person sees more and more of the same opinions or the same type of content.
  • The wrong goal. A system that only increases watch time can recommend content that is extreme or harmful, because it holds attention.
  • Fairness. A job system that learns from old hiring decisions can repeat old bias. Refer to Module 6, Section 3.
  • Privacy. The history of a person shows much about their life. Protect it, and tell users what data the system uses.

Good teams add variety, measure long-term satisfaction, and give users control, for example "Not interested" and "Show fewer items like this".

8

Summary

  • Content-based filtering recommends similar items. Collaborative filtering recommends what similar people liked.
  • Modern systems learn embeddings for users and items. The score is a dot product.
  • New users and new items have no history: the cold start problem.
  • Large systems work in stages: candidates, ranking, and rules.
  • Test with newer history, then with an A/B test. Measure long-term satisfaction, not only clicks.
  • Watch for feedback loops, filter bubbles, wrong goals, bias, and privacy problems.

10

Technical names

Candidate generation
The first stage of a recommendation system. A fast method selects some hundreds or thousands of possible items.
Cold start
The problem that a new user or a new item has no history.
Collaborative filtering
A method that recommends items that similar people liked.
Content-based filtering
A method that recommends items that are similar to the items that the person liked before.
Feedback loop
A loop in which the outputs of a model change the data that the model learns from next time.
Precision at k
Of the first k recommended items, the part that the user really used.
Recommendation system
A system that predicts which items a person will probably like, and shows those items first.
